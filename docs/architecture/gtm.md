# Google Tag Manager (GTM)

## What GTM is

[Google Tag Manager](https://tagmanager.google.com/) is a tag-management system that lets marketing configure and update third-party marketing/advertising tags (Google Ads, Facebook Pixel, LinkedIn Insight Tag, etc.) from the GTM web UI without needing a code deploy. The app's only responsibility is to load the GTM container and push semantic events onto the browser's `dataLayer`; GTM's own trigger/tag configuration (owned in the GTM UI, not in this repo) decides what happens with each event. The most common use case for GTM tags are to listen for one the events emitted from code and dispatch a corresponding event to a different marketing platform (i.e. Google Analytics, Linkedin, FB, etc) with a payload expected by that platform.

GTM is a separate system from [PostHog](/README.md#analytics---posthog), which this app also uses for product analytics and feature flags. Some user actions fire both a PostHog event and a GTM event from the same handler (see `SearchField.tsx`, `useCourseEnrollment.ts`) — they are independent tracking systems serving different consumers (marketing/ads vs. product analytics), not duplicates of each other.

## How it's used

### Loading the container

The GTM container is loaded in the root `(site)` layout: `frontends/main/src/app/(site)/layout.tsx`.

| Env var           | Purpose                                                                                                                    |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `GTM_TRACKING_ID` | GTM container ID (e.g. `GTM-NMJ2CT6T`)                                                                                     |
| `GTM_AUTH`        | GTM environment auth token (not a secret — scoped per GTM environment)                                                     |
| `GTM_PREVIEW`     | GTM environment/preview identifier (e.g. `env-3`). Matches the snippet provided by Google Tag Manager install instructions |
| `GTM_COOKIES_WIN` | Optional, defaults to `"x"` if unset. Matches the snippet provided by Google Tag Manager install instructions              |

If `GTM_TRACKING_ID`, `GTM_AUTH`, or `GTM_PREVIEW` is missing, GTM is skipped entirely. Local values live in `env/frontend.local.env`; see `env/frontend.local.example.env` and `env/shared.local.example.env` for the template (dev values are copied from the GTM Environments UI).

### Pushing events

All event-pushing logic lives in `frontends/main/src/common/analytics/gtm.ts`. At the bottom of the module is a single low-level primitive:

```ts
const pushGtmEvent = (event: string, payload: DataLayerPayload = {}) => {
  if (typeof window === "undefined") return
  try {
    window.dataLayer = window.dataLayer || []
    window.dataLayer.push({ ...payload, event })
  } catch {
    // Prevent analytics failures from impacting the app flow.
  }
}
```

Every tracked event is a small `track*` wrapper around `pushGtmEvent` that names the event and shapes its payload (e.g. `trackCourseEnrolled`, `trackSiteSearch`). Components and hooks call these wrappers directly — nothing calls `pushGtmEvent` or touches `window.dataLayer` outside this file. This keeps event names and payload keys centralized in one place rather than scattered as string literals across the app.

### UTM/traffic-source helpers

`frontends/main/src/common/analytics/utm.ts` parses `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, `gclid` and `li_fat_id` from the URL query string, and classifies traffic as Google-ad, LinkedIn-ad, or organic-social based on those values. These helpers back the arrival-tracking events described below.

## Adding a new event

1. Add a `track*` wrapper to `frontends/main/src/common/analytics/gtm.ts` that calls `pushGtmEvent` with a new, stable event name and an explicit payload shape (define a `type` for the payload if it has more than one field).
2. Call the wrapper from the component/hook where the user action or lifecycle moment actually occurs — don't call `pushGtmEvent` directly from application code.
3. Add the corresponding trigger/tag configuration in the GTM UI (outside this repo).
4. Update the tables above.
